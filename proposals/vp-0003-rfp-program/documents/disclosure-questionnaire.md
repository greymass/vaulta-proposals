## Purpose

This is the **standard conflict-of-interest declaration** required by the **Vaulta Network RFP Framework (Exhibit A to MSIG #5), sections 6.3a and 6.3c**, not an additional document. Everyone with a decision or approval right must answer the same questions **in the stated order**.

**Who files and when:**

| Who | When |
|---|---|
| **Steering Committee member** | Within **30 days**, running from the later of the execution of their appointment Resolution and the date VS LLC publishes the register as open for filing. **Signing weight and pay do not begin until it is filed** |
| **RFP Program Manager** | Before being recorded as **Manager of record** on any RFP |
| **Technical Reviewer** | Before being **assigned to any RFP** |
| **A member taking a Reviewer engagement** under Framework 12.6 | An **update**, filed **before the engagement begins**. The 10-business-day change window does not apply to it |
| **Anyone else given a decision or approval right** | Before that right takes effect |

Update within **10 business days** of any change and **refile annually**. An annual refiling more than **30 days overdue** suspends a member’s pay and bars Managers and Reviewers from new assignments until filed; **existing assignments continue** because late refiling is procedural, not a material breach (Framework 6.6).

## How to answer

| Rule | Requirement |
|---|---|
| **Answer every part** | In Parts 2–8, write **None** if there is nothing to declare; **a blank means the questionnaire is unfiled**. |
| **Use position bands** | Give the Part 4 band, **never an exact figure**. |
| **Protect third-party identities** | Name organizations where requested, especially in Part 5; **do not name individuals**, including relatives, colleagues, or counterparties. Describe the relationship instead. |
| **Declare first** | If a connection exists, declare it even if you consider it immaterial, and explain why; the Committee and readers assess materiality. |
| **When unsure, disclose** | Declare the connection and explain the uncertainty; an undisclosed relevant interest is a **material breach** under Framework 6.6. |
| **Sign your submission** | VS LLC writes it to the register **without altering its content** (Framework 6.3b). |

## The coded-answer schema

Store the **coded answers and full filing text in the same on-chain row**; the Portal reads and renders the register rather than keeping a separate copy. **Everything submitted is written permanently to the chain.**

### Form

A single ASCII string, pipe-delimited, version first:

```
VQ1|2.1:Y1|2.2:N|2.3:N|2.4:N|2.5:Y2|3.1:N|4.1:V0/Y0|4.2:N|4.3:N|5.1:Y2|5.3:R2|6.1:N|7.1:Y1|8.1:N
```

### Codes

| Code | Meaning |
|---|---|
| `N` | **None declared.** An explicit answer, not an absence |
| `Y`*n* | **Yes**, with *n* items set out in the full submission. *n* ≥ 1 |
| `V0`–`V4` | Position band (4.1) |
| `R`*m* | Recusal intended on *m* of the organizations named at 5.1 |
| `X` | **Not answered.** Invalid in a filed questionnaire |

**None and unanswered are different:** `N` declares nothing; any `X` means the questionnaire is **unfiled** under Framework 6.3c and Exhibit D 4.3.

### Rules a validator enforces

1. Every question in Parts 2 to 8 appears exactly once, in order.
2. No `X` in a filed questionnaire.
3. `5.3` is `N` if and only if `5.1` is `N`; otherwise `R`*m* with **0 ≤ *m* ≤ *n*** from `5.1`.
4. `4.1` carries both a band and a count: `V0` implies `Y0`, and any band above `V0` implies *n* ≥ 1.
5. A `Y`*n* answer requires *n* corresponding entries in the full submission. A mismatch fails validation.
6. The string is **stable for a given set of answers** — same answers, same string — so two filings can be compared by eye.

### What is written where

| | |
|---|---|
| **On-chain**, in the `disclosures` table on `disc.vst` | Everything: filer account, role, questionnaire version (`VQ1`), filing date, the coded string above, **the full text of your answers** — organizations named, the nature of each connection, every reason and explanation — and, on an update, the transaction id of the filing it supersedes and the reason |
| **On the Portal** | Nothing separately. The Portal **reads the register** and renders it |
| **Nowhere, ever** | Exact position figures, and the **names of individuals** |

**Review before signing: filings cannot be edited, redacted, or withdrawn.** VS LLC must return, rather than publish, a filing naming individuals or giving exact position figures where bands were requested; this is a **mechanical screen, not a review of substance**.
