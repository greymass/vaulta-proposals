---

## How to use this template

One proposal may name **one candidate for one seat**, a **full slate** of the four staggered seats, or **any subset** — for example Business Development and Marketing together. Use whichever grouping reflects how the candidates were actually put forward.

Block producers may approve more than one proposal covering the same seat. Where more than one reaches 15 of 21, **the seat goes to whichever proposal executes first by block time**.

**Seats resolve independently by default.** A proposal that names four seats and executes when one of them is already filled seats the other three, and has no effect for the filled one. Where the combination matters — because the candidates were chosen to balance each other — mark the proposal **all-or-nothing** in the field below, and it will have no effect at all if **any** named seat fails for **any** of the conditions listed in the Resolved Clauses, not only because it is already filled.

**Row order is priority order.** If two candidates in the same proposal conflict with each other — the same person named twice, or two people from the same organization — the seats are tested in the order the rows appear in the Candidates table. The first takes effect; the later has no effect. Order the rows deliberately, and reorder them if the default order is not the priority you want.

Before proposing, check every candidate against the eligibility conditions, the **published register of bans**, and the affiliation rule. A proposal that would breach them has no effect for the affected seat even if executed.

**Proposal name suggestion:** `sc` plus the seats covered — `scdevalice` for one, `scslate1` for a full slate, `scbdmkt` for a pair. Block producers will be choosing between several at once, so make it recognizable.

## Before you propose — the completeness check

MSIG #5 Part B sets out what makes an Exhibit E proposal complete. **A proposal missing any of these is incomplete, and block producers should decline it rather than approve it and correct it afterwards.**

| | Have you |
|---|---|

| 4 | Stated the **resolution mode** |
| 5 | Included a **network vision statement per candidate**, written by that candidate |
| 6 | Included **relevant background and declared conflicts** for each candidate |

## Notes for block producers

**You may approve more than one proposal covering a seat.** Doing so signals support for each. It does not rank them — the outcome turns on which proposal executes first, not which has the most approvals. If you have a clear preference, approving only that one is the stronger signal.

**Watch the resolution mode on slates.** A seat-by-seat slate can be partially seated; an all-or-nothing slate cannot. If a slate was assembled so the four candidates complement each other, all-or-nothing preserves that. If the candidates stand on their own merits, seat-by-seat wastes fewer passed votes.

**Cancel losing proposals.** Once a seat is filled, proposals covering it should be cancelled. An approved proposal left on-chain can be executed later by anyone, and while this template makes such an execution ineffective for a filled seat, cleaning up avoids the confusion.

**Read the vision statements.** They are the part of the proposal that tells you what a candidate would actually do with the seat — what they would fund, and more usefully what they would decline. Where several candidates stand for the same seat, this is the comparison. A proposal that does not carry one is incomplete; decline it and ask the proposer to complete it rather than approving on a name and a biography.

**Check the seat register before executing.** It is on the Portal and is the canonical record of who holds each seat — parallel proposals can leave executed-but-ineffective appointments on-chain.
